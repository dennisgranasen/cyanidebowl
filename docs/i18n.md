# UI localization

BlaskScore localizes interface chrome, labels, statuses and formatting. Editorial
content (articles, comments and other user-authored prose) is deliberately not
translated.

## Locale resolution

The effective UI locale is resolved in this order:

1. Signed-in user's explicit `WarpScoresUser.locale`.
2. For anonymous visitors only, `localStorage["blaskscore.uiLocale"]`.
3. Site administrator's `SiteSettings.defaultLocale`.
4. Hard fallback: Swedish (`sv`).

A null user locale means "follow site default". Do not copy the current site
default into new user records.

## Supported locales

Production-quality message catalogs:

- `sv` — Swedish
- `en` — English
- `es` — Spanish
- `fi` — Finnish
- `pl` — Polish

Experimental Tolkien-language UI locale identifiers:

- `sindarin`
- `quenya`
- `khuzdul`
- `entish`
- `nandorin`
- `black-speech`

The experimental locales intentionally inherit the English catalog for missing
messages. Do not invent translations merely to reach 100% coverage. Add a
fictional-language message only when its vocabulary and grammar have been
reviewed against a reliable corpus. This is especially important for Khuzdul,
Entish, Nandorin and Black Speech, whose attested vocabularies are too limited
for a complete modern web UI.

## Adding UI text

Use `react-intl` message IDs. Never use the English prose itself as the ID.

```jsx
const intl = useIntl();
intl.formatMessage({ id: 'competition.standings' });
```

Add the English source message first, then all production language translations.
The English catalog is merged underneath every selected catalog so an omitted
message never renders as an ID.

## Not localized

- Article titles/bodies
- Comments
- AI reporter prose already stored as editorial content
- Team, coach, league and competition names supplied by source systems

Those values may carry language metadata in the future, but UI locale selection
must never rewrite them.
